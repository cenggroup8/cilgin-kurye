# Shared contracts

These files are the agreements between modules. Every module may read them;
nobody changes them alone. A change needs a pull request and approval from each
module that uses the file.

| File | Used by | Owner |
| --- | --- | --- |
| `city_plan.json` | M1, M3, M4, M6 | M1 (M6 reviews) |
| `board_protocol.md` | M1, M2, M6 | M6 (M2 reviews) |
| `board_protocol_vectors.json` | M2, M6, tools | M6 (M2 reviews) |
| `messages.md` | M1, M2, M4, M5 | M1 and M2 |

Both JSON files are generated by the scripts in [`tools/contracts/`](../tools/contracts).
Edit the script, not the JSON, and run the check before a pull request.

`messages.md` has the phone and admin messages (M2-2, #35). The fields of the game state
and the messages between M1 and M3 are not here yet; they come with M1-1 (#29).

## Coordinates

- World units: metres, seconds, degrees.
- Origin at intersection `n_0_0` (north-west corner). x to the east, z to the south, y up.
- Heading in degrees, clockwise from north.
- Board coordinates: `u = x / size_m`, `v = z / size_m` (0 to 1).

Everything that goes from one module to another uses these coordinates, also between
M1 and M3: a pose is `x`, `z` in metres and `heading` in degrees, clockwise from north
(0 north, 90 east, 180 south, 270 west). A module may use other axes or radians inside.
It converts at its own border, in one file (for example `M3-physics-traffic/src/common/coords.ts`).

## ID rules

The city has a 6 × 6 grid of intersections and 60 road segments.
IDs come from formulas, so no module needs a lookup table.

| Item | Name | ID |
| --- | --- | --- |
| Intersection, row r, column c (0–5) | `n_r_c` | `6r + c` (0–35) |
| East–west segment from `n_r_c` to `n_r_(c+1)` | `h_r_c` | `5r + c` (0–29) |
| North–south segment from `n_r_c` to `n_(r+1)_c` | `v_r_c` | `30 + 6r + c` (30–59) |
| Block between rows r, r+1 and columns c, c+1 (0–4) | `b_r_c` | `5r + c` (0–24) |

## Zones

The earthquake and the board use 9 zones in a 3 × 3 grid over the 500 m × 500 m city:
`zone = 3 × row + column`, row 0 in the north, column 0 in the west (`board_protocol.md`).
The centre of a zone, in metres:

    x = (column + 0.5) × 500 / 3
    z = (row + 0.5) × 500 / 3

So zone 0 has its centre at about (83.3, 83.3), zone 4 at (250, 250) and zone 8 at about (416.7, 416.7).

## Lanes

Every segment has 2 lanes in each direction. An obstacle or event names a lane with a number:

| Lane | Meaning |
| --- | --- |
| 0 | The whole road |
| 1, 2 | Driving in the direction of the segment (`h_r_c` to the east, `v_r_c` to the south) |
| 3, 4 | Driving the other way |

1 and 3 are next to the centre line, 2 and 4 are at the side of the road. Traffic drives
on the right. A module that counts lanes in another way converts at its own border.

## Buildings

`buildings` in `city_plan.json` has one box per block until the 3D model is ready (#22, K8/K9):
`{ id, block, footprint: [[x, z], ...], height_m }`. The footprint is in metres, corners clockwise
seen from above. A building stays 10 m from the road centre line (2 lanes of 3.5 m and a 3 m
sidewalk). In the four corner blocks the store corner (30 m × 30 m) is left free. Heights are
placeholders (12–36 m). The 3D model file belongs to M5.
